# Art direction and image prompts

> **Status:** style guidance and prompt library. The global map already exists. Images are generated by the owner in ChatGPT, never by Claude Code (`docs/ASSET_PROTOCOL.md`). Sections on journey strips and the Together image spike describe future place maps only; ignore any step that has Claude Code generating images.


Status: DRAFT. Claude Code fills the brand slots (§2) from the brand presentation in Milestone 0; the owner approves before bulk generation.

## 1. Principles
- **Illustrated realism, not photorealism.** Recognizable real-life places with believable proportions and details, drawn as soft vector-style illustration that matches the Feelio mascot. No photo look and no 3D render.
- **Calm and inviting.** Soft light, no dark or scary corners, no clutter. Children should instantly read where things are.
- **Scenes are empty stages.** Background plates contain no people, no text, no logos. Characters, markers and UI are added in code so they stay consistent and editable.
- **One camera.** Every plate is a straight-down map view at the same aspect ratio and lighting logic, so the world feels like one place.
- **Culturally neutral base.** The base world has no region-specific landmarks, architecture, flags, symbols or traditional dress, so it feels at home in any country. Region-specific looks belong to separate world packs (see §6), never to the base.

## 2. Brand slots (filled from the Feelio brand presentation; verify hex values against the source files)
- Palette (hex): amber #F3B03A, rose #C4557C, purple #614194, blue #79B1DE; tints #FFE6BA, #FFD8E6, #EFCFF8, #D4ECFF. Backgrounds in the deck are pale lilac with white clouds.
- Line and texture: soft vector illustration, rounded shapes, smooth gradients, gentle glossy highlights on characters, no paper grain.
- Mascot (reference only; never generated): a round glossy blob with an antenna orb, dark blue screen face with sparkle eyes, pink cheeks, a heart on the belly, amber-to-purple gradient body.
- Shapes and mood words: soft, cheerful, playful, innocent, friendly; sparkles, clouds, dashed hand-drawn loops.
- The presentation states no "avoid" rules. Our additions: no photorealism, no dark or scary scenes, no text in images.
- Because the mascot is glossy vector art, scene plates must match that language so the composited mascot doesn't look pasted on. Prefer soft vector-like plates with gentle gradients over painterly textures.

## 3. Journey map: the approach
The world is one endless, scrolling journey, like a level-select map in a mobile game. Each place (Park, Home, School, Market, Club, and any future place) is one **zone**, a stretch of scenery along the journey. A new place is simply appended to the end.

**What is generated and what is code**
- **Generated (AI):** one scenery strip per zone: top-view background art with the landmarks along the left and right sides and an open, empty corridor in the middle. No path, no buttons.
- **Code:** the winding dashed path, the numbered level nodes and their locked, current and completed states, the mascot marker, zone banners at the seams (with the place's name), fog over upcoming zones, and the pop-up for each level. All of it comes from data, so it is crisp, brand-consistent, easy to change, and continuous across zones.

Because the path is drawn in code, the strips never have to line up with each other, which is the part image models are worst at.

**Stacking rule.** Every strip has a plain, soft light-green meadow in its top 10% and bottom 10% (standard seam color, to be confirmed in Milestone 0, about #C5E8A5). Strips can then be stacked in any order and the seam is hidden by a code-drawn banner and a soft blend.

**Orientation**
- **Vertical (phone, primary):** the journey scrolls vertically, one strip per zone, 9:16.
- **Landscape tablet (default, no extra art):** a split view with the journey as a column on one side and the companion and scenario panel on the other.
- **Horizontal strips (optional):** a second art set, only if we want the journey to scroll sideways on tablets. Prompts are below.
- Right-to-left languages mirror the journey horizontally in code. The art contains no text.

## 5b. Composition and production rules
- **Sizes.** Vertical: drafts 720×1280, finals 816×1440. Horizontal: drafts 1280×720, finals 1440×816. Export WebP, 400 KB or less per strip.
- **Corridor.** The central half of the image stays open so the code-drawn path can wander through it. Landmarks sit outside it.
- **Checkpoints.** About five per zone. Their positions live in the zone's data (offset along the strip and sideways inside the corridor, near each landmark) and are alternated left and right so the path S-curves.
- **Exactness doesn't matter.** If a strip has landmarks slightly off, move the checkpoint in data. If the corridor is blocked, regenerate or edit the image.
- **Seams.** Hidden by a code-drawn zone banner (the place name in each language) and a soft blend; never rely on edges matching.
- **Locked and future zones.** The next zone is desaturated under code-drawn fog. The end of the journey shows a "more coming soon" cloud and later the travel node to a new pack.
- **Endless scrolling.** Load only the strips near the viewport (virtualized), lazy-load the next strip, and measure bandwidth on Vercel Hobby.
- **Alt text.** Each zone gets a description and each checkpoint a label.

## 6. World packs and regional variants (future: "Feelio visits ___")
The base world stays culturally neutral. Regional looks arrive later as world packs (see `SPEC.md` §4.4), where Feelio travels to a country or region and plays through a few levels there.

For each pack, write a **pack style addendum**, a short block inserted between the master style block and the place prompt:

> Setting: [REGION OR COUNTRY]. Architecture and materials: [...]. Plants and landscape: [...]. Everyday objects and food: [...]. Colors and light: [...]. Avoid: [stereotypes, flags, sacred sites, caricatures].

Rules for packs:
- Write the addendum with, or have it reviewed by, people from that region (parents, teachers, or child-development experts), not by guesswork or the image model alone.
- Show everyday life, not tourist clichés. No stereotypes, no caricatured clothing, no flags or religious symbols unless a local reviewer asks for them, and no depictions of sacred sites.
- Reuse the same master block, camera and lighting so the pack still looks like our world.
- Each pack needs its own approved anchor plate and, if it has new characters, its own cast sheet.
- Do not start any pack art until the base world ships.

## 7. Workflow
1. **Spike:** generate 4 candidates of the Park strip (vertical) with 2 candidate models. Compare style, detail, cost per image and how well each follows "no people, no text".
2. **Approve the anchor:** I pick one Park strip. Save it as the style reference.
3. **Other places:** generate with the same master block and, if the model supports it, the anchor as a style reference. Generate 4 candidates per place, keep the best, and regenerate only what fails.
4. **Review:** Claude Code opens each candidate, applies the checklist in §8, and gives me a shortlist with reasons.
5. **Export:** convert the approved plate to WebP, write alt text, add it to `assets/manifest.json`, and define the tap regions in the pack's `world.json`.
6. **Prop and animation extras (later):** small animated props (swinging swing, drifting clouds, ducks) as SVG or CSS, drawn in code, not generated.

## 8. Rejection checklist
Reject a candidate if it has: any person or face; any readable or fake text; distorted or melted objects; a different art style or lighting from the anchor; dark or unsettling areas; too many tiny details to tap; landmarks that overlap or are hidden; a cluttered bottom third.

## 9. Supporting cast (design once, approve, reuse)
Scenarios need other children and family members besides the mascot. Do not generate them ad hoc. The base cast should be diverse and not tied to one region. Design a small cast (about 4 children of different looks and one or two adults) as a single approved sheet with front, three-quarter and side views and 5 expressions, in the same style as the plates. Template:

> Character design sheet for a children's game, [AGE]-year-old [DESCRIPTION], friendly, simple clothing in the palette [PALETTE], same soft vector style as the backgrounds and the Feelio mascot, shown in front, three-quarter and side views plus five expressions (happy, sad, angry, scared, surprised), plain light background, no text.

Approve the cast sheet before any scenario art is made. Expect to iterate and hand-correct; consistency across many images is the hardest part, so keep the cast small and reuse approved images.
